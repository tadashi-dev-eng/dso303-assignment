# Service documentation

Every service in the production architecture, why it was picked over the obvious alternative, how it is configured (all values come from `infra/*.tf`) and what it connects to.

| Service | Role | Why over an alternative | Configuration | Connects to |
|---|---|---|---|---|
| **Amazon Route 53** | Public DNS for `exams.example-university.edu` | Alias records to CloudFront are free and resolve at the apex, which a CNAME at another DNS host cannot do. 100% SLA. | Public hosted zone; `A` alias → CloudFront (`edge.tf`) | CloudFront, ACM (DNS validation) |
| **Amazon CloudFront** | Serves the SPA and fronts the API under `/api/*` | One HTTPS origin for the browser, so there is no CORS preflight on every autosave. TLS ends at the edge closest to students (PriceClass_200 includes India). Cheaper and faster than serving the SPA from the API. | Two origins: S3 (OAC, `CachingOptimized`) and API Gateway (`CachingDisabled`, `AllViewerExceptHostHeader`); `redirect-to-https`; TLS ≥ 1.2_2021; access logs to the logs bucket | Route 53, WAF, S3 frontend, API Gateway, ACM |
| **AWS WAF** | Layer-7 filtering at the edge | Managed rule groups block OWASP-style attacks without running and patching a proxy fleet. Shield Standard is included. | Web ACL (scope CLOUDFRONT): `AWSManagedRulesCommonRuleSet` (body-size rule set to *count*, because answer payloads can exceed 8 KB), `KnownBadInputs`, and a **20,000 req / 5 min per-IP** rate rule. The limit is high on purpose because a whole exam hall shares one campus NAT IP. | CloudFront, CloudWatch metrics |
| **AWS Certificate Manager** | TLS certificate for the custom domain | Free, auto-renewing public certificates (a bought certificate expires and must be rotated by hand). | DNS-validated, in us-east-1 so CloudFront can use it | CloudFront, Route 53 |
| **Amazon S3 – frontend bucket** | Hosts the built single-page app | Static hosting costs cents and scales without limit. An EC2/nginx web tier would need patching and capacity during the exam peak. | Block Public Access on; readable only by CloudFront via an OAC bucket policy; SSE-S3 | CloudFront |
| **Amazon Cognito user pool** | Role-based sign-in (students, tutors, admins) | Managed OIDC/JWT issuer whose groups map directly to roles. API Gateway validates its JWTs natively, so no auth code runs in Lambda. Hosting Keycloak would add servers to keep highly available. | Email usernames, admin-create-only, 12-character password policy, optional TOTP MFA, groups `students` / `tutors` / `admins`, 4-hour tokens (longer than any exam) | API Gateway (JWT authorizer), frontend |
| **Amazon API Gateway (HTTP API)** | Public API front door with authentication and throttling | HTTP API costs about 70% less than a REST API and has a built-in JWT authorizer. An ALB would need a VPC public tier and its own auth. It is multi-AZ by design. | JWT authorizer (Cognito issuer and audience) on every route except `/health`; stage throttling **burst 5,000 / rate 2,000 rps**; JSON access logs to CloudWatch (90 days) | CloudFront, Cognito, api Lambda (`live` alias) |
| **AWS Lambda – api** | Exam, attempt, autosave, upload-presign and results-release logic | Scales from 0 to thousands of concurrent executions within seconds, which is exactly the 3,000-students-in-5-minutes shape. ECS/EC2 would need pre-scaling and pay for idle time between exam weeks. | Node.js 20, arm64, 512 MB, 10 s timeout; **reserved concurrency 600**; **provisioned concurrency 300** on the `live` alias during exam windows (`scripts/exam-window.sh`); in the **private app subnets of both AZs**; X-Ray tracing; least-privilege role | API Gateway, DynamoDB, Aurora (Data API), S3, SQS, Secrets Manager, KMS |
| **AWS Lambda – marker** | Auto-marks MCQs from the marking queue | Marking is bursty and runs after the exam, so pay-per-use beats an always-on worker. SQS triggers give retries and partial-batch failure for free. | 256 MB, 60 s, reserved concurrency 50 (cannot starve the API), batch size 10 with a 5 s window, `ReportBatchItemFailures`; private app subnets of both AZs | SQS marking queue, DynamoDB, Aurora |
| **AWS Lambda – notifier** | Records uploads, emails tutors (new submission) and students (results) | Same reasons as the marker. It runs **outside the VPC** because it only calls public AWS APIs, so it has no NAT dependency and is unaffected by losing an AZ's NAT gateway. | 256 MB, 60 s, reserved concurrency 50; consumes the uploads and notify queues | SQS, S3, DynamoDB, Aurora (Data API), SES |
| **Amazon Aurora PostgreSQL** | System of record: users, courses, exams, questions/answer keys, attempts, results | Relational integrity for marks and results. Aurora keeps 6 copies across 3 AZs and fails over in about 30 s. The **Data API** removes connection pooling for thousands of Lambdas (no RDS Proxy needed). Plain RDS Multi-AZ fails over more slowly and needs a proxy. | Writer in **us-east-1a**, reader and failover target in **us-east-1b** (`promotion_tier`); private data subnets only; SG allows 5432 from the Lambda SG only; KMS encrypted; **35-day continuous backup (PITR)**; IAM auth; deletion protection; logs to CloudWatch | api, marker and notifier Lambdas, Secrets Manager, KMS, AWS Backup |
| **Amazon DynamoDB – attempts** | Autosave store for in-progress answers | Single-digit-ms writes at any scale with no connections. On-demand absorbs ~100 writes/s at peak (3,000 students ÷ 30 s) with no capacity planning. Autosaving into Aurora would put 100 TPS of tiny writes on the exam-critical database. | On-demand; key `attemptId` + `questionId`; conditional writes (`clientTs` must increase, so a late retry never overwrites a newer answer); **PITR** (RPO of seconds); KMS CMK; deletion protection | api and marker Lambdas, gateway endpoint, AWS Backup |
| **Amazon DynamoDB – submissions** | Register of uploaded assignments for tutors | Key-value lookups by course through a GSI. There is no need for joins. | On-demand; GSI `byCourse`; PITR; KMS CMK | notifier (write), api (tutor query) |
| **Amazon S3 – submissions bucket** | Stores assignment files (PDF/ZIP ≤ 50 MB) | Cheaper and more durable (11 nines) than EBS/EFS. **Presigned PUT URLs keep 50 MB uploads off the API**: Lambda has a 6 MB payload limit and API Gateway a 10 MB limit. | Versioning on; SSE-KMS with bucket key; Block Public Access; TLS-only bucket policy; CORS `PUT` from the site origin; the presigned URL signs **Content-Length and Content-Type** (15 min expiry); **lifecycle**: Standard → Standard-IA at 30 days → Glacier IR at 180 days → Deep Archive at 365 days → delete at 5 years + 30 days; abort incomplete multipart uploads after 1 day | Browser (presigned PUT), api, notifier, SQS (events), KMS |
| **Amazon S3 – logs bucket** | CloudFront and CloudTrail logs | Cheapest durable log sink | Lifecycle: Glacier IR at 30 days, expire at 365 days | CloudFront, CloudTrail |
| **Amazon SQS** (marking, notify, uploads + 3 DLQs) | Decouples marking and email from the request path | Buffers the burst when 3,000 attempts are submitted at once, and a failed marker never fails the student's submit. SNS alone has no buffering or retry window, and EventBridge would add cost without benefit here. | Standard queues; visibility timeout ≥ 6× the function timeout; **DLQ after 5 receives** (14-day retention); KMS (marking, notify) / SSE-SQS (uploads, which S3 notifications require) | S3 events, api, marker, notifier, CloudWatch alarms |
| **Amazon SES** | Sends results-released and new-submission emails | Pennies per thousand emails with DKIM/SPF support. SNS email topics cannot address individual students. | Verified sender identity `no-reply@…`; production access (out of sandbox) | notifier Lambda |
| **AWS Secrets Manager** | Aurora master credentials | Encrypted, audited and rotatable. SSM Parameter Store has no built-in RDS rotation. | KMS CMK, 7-day recovery window; managed RDS rotation can be switched on (not yet in Terraform) | Aurora, all Lambdas (Data API `secretArn`) |
| **AWS KMS** | Customer-managed key for data at rest | One auditable key with rotation and key policy across Aurora, DynamoDB, S3, SQS, Secrets and CloudTrail. AWS-owned keys give no audit trail or control. | Annual automatic rotation, 30-day deletion window, alias `alias/exams-prod-data` | Aurora, DynamoDB, S3, SQS, Secrets Manager, CloudTrail |
| **Amazon VPC** | Network isolation across **two AZs** | Required for the private data tier. Three subnet tiers per AZ keep the database unreachable from the Internet. | `10.20.0.0/16`; public `/24` ×2, private-app `/20` ×2 (room for Lambda ENIs), private-data `/24` ×2; the data tier has **no Internet route** | All in-VPC resources |
| **Internet Gateway + NAT Gateway ×2** | Egress for the private app subnets | **One NAT per AZ**, each app route table pointing at its own AZ's NAT, so losing AZ-a never cuts egress for AZ-b. A single NAT is a cross-AZ single point of failure. | EIP per NAT; route tables `rt-app-a` → `nat-a`, `rt-app-b` → `nat-b` | Public subnets, private app subnets |
| **VPC Gateway Endpoints (S3, DynamoDB)** | Private path to S3 and DynamoDB | Free, keeps autosave traffic off the NAT (no per-GB NAT charge or NAT dependency), and traffic never leaves AWS. | Attached to both app route tables | api/marker Lambdas, S3, DynamoDB |
| **Security Groups** | Instance-level firewall | Stateful SG-to-SG references are tighter than CIDR rules | `lambda-sg`: egress 443 and 5432 to data subnets; `db-sg`: 5432 from `lambda-sg` only | Lambda, Aurora |
| **Amazon CloudWatch** | Logs, metrics, alarms, exam-day dashboard | Native to every service used. A self-hosted Prometheus/Grafana stack would need its own HA. | Log groups with 90-day retention; alarms: API 5xx, p95 latency > 1.5 s, Lambda throttles, DLQ depth ≥ 1, marking backlog age > 15 min, Aurora CPU > 80%; dashboard `exam-day` | SNS alarm topic, every service |
| **Amazon SNS** | Ops alarm fan-out | Simple push to email/SMS/chat for alarms | Topic encrypted with `alias/aws/sns`, email subscription to ops | CloudWatch alarms |
| **AWS CloudTrail** | API audit trail | Required for a regulated records system. It is free for management events. | Multi-region, log-file validation, KMS, stored in the logs bucket | S3 logs bucket, KMS |
| **AWS Backup** | Long-term retention of records (5 years) | One policy for Aurora and DynamoDB with vault lock options. Snapshot scripts are error-prone. | Daily backups kept 35 days; monthly backups moved to cold storage after 90 days and **deleted after 5 years**; KMS vault | Aurora, DynamoDB |
| **AWS IAM** | Least-privilege execution and deploy roles | Fine-grained per-function policies (`compute.tf`). The CI role uses **GitHub OIDC**, so there are no long-lived keys. | One role per Lambda scoped to exact ARNs; deploy role trusted only for `repo:<repo>:ref:refs/heads/main` and the `production` environment | Every service |
| **GitHub Actions + Terraform** (CI/CD) | Reproducible infrastructure and automatic redeploy | Terraform is cloud-agnostic, reviewable in PRs and supports plan files. Remote state lives in S3 with a DynamoDB lock. CodePipeline would be another console-managed resource to keep in sync. | `ci.yml`: fmt, validate, `node --check`, shellcheck, plus a **full Floci integration run** (deploy, walkthroughs, AZ failure, destroy). `deploy.yml`: on push to `main`, OIDC → `terraform plan` → (protected `production` environment) `apply` → DB migration → smoke test | AWS (via OIDC role), S3/DynamoDB state backend |
